# 02: 抽出「比價流程入口」（預先重構，行為不變）

**Parent:** [規格書](../spec.md)

**What to build:** 把目前寫在 LINE webhook 處理函式內的整段比價邏輯，搬到一個獨立的「比價流程入口」：輸入文字或圖片，輸出不含任何 LINE 格式的結構化「比價結果」。AI 解析器、各平台抓價、時鐘、快取皆以依賴注入傳入。Webhook 改為呼叫此入口，再把比價結果交給卡片產生器轉成 Flex 卡片。使用者看到的回覆與重構前完全相同。這是後續所有票的基礎（規格書的測試切入點 1）。

**Blocked by:** 01

**Status:** done（待手動 LINE 驗證）

- [x] 存在單一的比價流程入口，接受「文字」或「圖片」其一，回傳結構化比價結果（商品名稱、搜尋關鍵字、各平台狀態與價格、搜尋連結、取得時間、是否來自快取）
- [x] 比價流程入口不依賴任何 LINE SDK 型別
- [x] AI 解析器、平台抓價函式、時鐘、快取可由呼叫端替換
- [x] Webhook 只負責：驗證、Rich Menu 指令、限流、呼叫入口、把結果轉成卡片並回覆
- [x] 卡片產生器接受比價結果作為輸入
- [x] 新增從入口測試的案例（假解析器＋假平台）：成功、部分平台失敗、全部失敗、快取命中
- [x] 既有直接替換 webhook 內部函式的整合測試，改為接到入口或 webhook 切入點；測試全數通過
- [ ] 手動以 LINE 傳一則文字與一張圖片，回覆與重構前一致


**Notes（實作後）：**

  → 已於 [04](04-platform-adapter-interface.md) 完成：各平台連結改放在 `PlatformQuote.search_url`，卡片產生器不再自行組連結；`PlatformFetchers` 由平台集合（`platforms=`）取代。

- `ComparisonResult.parsed_item / pricing / scraper_result` 為舊卡片的過渡欄位。
